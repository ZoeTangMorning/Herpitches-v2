## 1. 产品概述

### 1.1 产品定位

面向普通球迷和深度球迷的 WSL（英格兰女子超级联赛）资讯平台。本次首版只做 WSL 内容，为用户提供及时、易读的资讯，可信的赛事与球员数据，以及受控的评论互动空间。

首版由三个并列模块组成：

1. **新闻**：WSL 新闻、专题、人物内容与图文战术解析。
2. **数据**：WSL 赛程赛果、积分榜、球队、球员与比赛基础数据。
3. **主队**：用户选择并追踪的主队内容入口。
4. **社区**：围绕 WSL 内容的评论、点赞与举报，不提供用户独立发帖。
5. **我的**：登录、收藏、提醒设置、评论记录和通知授权状态。

### 1.2 产品目标

- 让普通球迷能快速了解 WSL 热点、赛事进程和关注球队的动态。
- 让深度球迷能连续查看 WSL 赛事、球队、球员及比赛基础数据，并阅读战术内容。
- 通过主队、关注和赛事提醒，建立用户对球队、球员和赛事的持续追踪。
- 通过先审后发的评论机制，建立有秩序的轻量互动氛围。
- 提供可安装、适合移动端、可离线阅读近期内容的 PWA 使用体验。

### 1.3 非目标

以下内容不属于首版范围：

- 独立运营后台、推荐编排后台和运营数据报表。
- 视频优先内容、直播流、集锦版权接入或用户上传视频。
- 用户发帖、话题广场、私信、群聊等开放式社区能力。
- 传球网络、射门热区、阵型演变等进阶战术数据可视化。
- 英文、繁体中文或其他多语言界面。
- 其他联赛和国际赛事内容。
- 自建赛事数据采集系统；首版仅预留第三方数据接口适配能力。

## 2. 用户与权限

### 2.1 目标用户

| 用户 | 核心诉求 | 典型使用场景 |
| --- | --- | --- |
| 普通球迷 | 快速获知热点、赛程和赛果 | 通勤时浏览新闻、赛前查看开球时间、赛后查看结果 |
| 深度球迷 | 获取完整基础数据和深度内容 | 跟踪联赛积分、查看球员数据、阅读比赛与战术分析 |
| 已登录用户 | 建立个人关注和参与互动 | 关注球队或球员、订阅提醒、评论、点赞和举报 |

| --- | --- | --- | --- |
| 浏览资讯、赛事和数据 | 支持 | 支持 | 支持 |
| 搜索与筛选内容 | 支持 | 支持 | 支持 |
| 安装 PWA、阅读已缓存内容 | 支持 | 支持 | 支持 |
| 关注球队、球员、赛事 | 不支持 | 支持 | 不适用 |
| 选择和切换主队 | 不支持 | 支持 | 不适用 |

## 3. 信息架构与页面

### 3.1 一级导航

- **数据**：WSL 赛事日历、赛程赛果、积分榜、球队、球员和比赛详情。
- **新闻**：WSL 新闻、专题、人物、战术四类内容的聚合与筛选。
- **主队**：已选主队概览，未选时显示引导入口。
- **社区**：围绕 WSL 内容的评论、点赞与举报。
- **我的**：登录、关注列表、收藏、提醒设置、评论记录和通知授权状态。

移动端使用底部导航承载一级入口；桌面端使用顶部主导航。页面必须在窄屏下保持单列、可读、可操作。

| 页面 | 核心内容与操作 |

## 4. 功能需求

### 4.1 资讯阅读

#### 内容类型

- **新闻快讯**：WSL 赛事动态、转会、伤停、赛前赛后报道、八卦新闻和官方公告。
- **赛事专题**：围绕 WSL 的聚合页，包含背景、赛程、相关报道和数据入口。
- **人物内容**：球员、教练及相关从业者的采访、档案和故事。
- **战术解析**：以图文为主的阵容、打法、关键回合和赛后分析；首版不要求进阶数据图表。

#### 用户能力

- 按关键词搜索资讯标题、摘要、球队、球员和赛事名称。
- 按内容类型、WSL 赛事、球队或发布时间筛选资讯。
- 在资讯详情页浏览关联对象，并跳转至赛事、球队或球员页。
- 已登录用户可收藏资讯；游客可在当前设备保存临时阅读记录。
- 已登录用户可关注资讯关联的球队、球员或赛事。
- 最近阅读和近期资讯应纳入离线缓存范围。

#### 内容状态

- 正常发布内容可公开浏览。
- 被下线或删除的内容不再出现在列表和搜索结果中。
- 内容更新时保留更新时间；重大更正应显示更正说明。

### 4.2 数据工具

#### 赛事与赛程

- 提供 WSL 赛事列表和赛季结构。
- 支持按赛事、日期、球队和比赛状态查看赛程与赛果。
- 比赛状态至少区分：未开始、进行中、已结束、延期、取消。
- 比赛详情展示开球时间、对阵双方、比分、比赛事件、基础技术统计和首发/替补阵容。
- 用户在比赛详情页向下滑到底部时，可查看本场比赛的阵型与战术解读。
- 阵型与战术解读以图文为主，包含双方阵型、首发站位说明、关键球员角色、进攻/防守思路和比赛关键战术变化。
- 若某场比赛暂无阵型或战术解读，底部区域显示“暂未提供”，不影响比分、阵容和基础数据浏览。
- 用户点击比赛阵容中任一可用球员的头像，可进入该球员的数据页。
- 开球时间按用户设备本地时区显示，并保留赛事原始时间数据。

#### 积分榜

- 按赛事和赛季查看积分榜。
- 展示排名、球队、场次、胜平负、进失球、净胜球和积分。
- 当赛事规则存在特殊排名或分组阶段时，前台以数据接口提供的官方排序为准。
- 显示数据最近更新时间；数据延迟或不可用时显示对应状态。

#### 球队与球员

- 球队页展示基础资料、所属 WSL 赛事、近期赛程赛果、积分表现、球员名单及相关新闻；用户点击名单中任一可用球员的头像，可进入该球员的数据页。
- 球员页展示名称、头像、原文名、国籍、出生时间、位置、所属俱乐部、转会记录、基础资料、赛季基础数据、俱乐部官网的介绍、近期比赛及相关新闻；用户点击所属俱乐部标识，可进入该球队的数据页。
- 球员基础数据至少支持出场、首发、进球、助攻、黄牌、红牌和出场时间；缺失字段不以零值伪造。
- 所有球队、球员和赛事名称支持原文名称和中文名称展示，球员名称由原名在前中文名在后；中文别名可作为搜索索引。

#### 实体跳转与可用性

- 球员头像和俱乐部标识使用关联实体的唯一标识进行站内同窗口跳转，不打开新标签页。
- 仅当关联的球员或球队存在、未下线且有可访问的数据页时，头像或标识才提供跳转能力。
- 关联实体缺失、已下线或数据页不可用时，头像或标识保持非跳转状态，并提供“数据暂不可用”的可见提示。
- 头像或标识图片加载失败时，保留球员或俱乐部名称的文字替代显示；有效关联关系不受图片失败影响。
- 可跳转的头像和标识必须具备可访问名称、键盘聚焦与 Enter/Space 触发能力；移动端点击区域应易于触达。

#### 数据展示原则

- 明确展示最近更新时间。
- 数据缺失时展示“暂未提供”，不使用推测值或空白统计卡。
- 数据异常、接口超时或供应商不可用时，保留最近一次成功数据并标识可能已过期；无缓存数据时展示错误提示与重试入口。

### 4.3 社区互动

#### 评论

- 评论仅挂载于资讯详情页，首版不提供独立帖子和话题广场。
- 游客可浏览已审核通过的评论；登录用户可发表、删除自己的评论，并查看审核状态。
- 新评论默认进入“待审核”，审核通过后才对其他用户公开。
- 评论应支持回复一层；首版不支持无限层级讨论。
- 被拒绝、删除或屏蔽的评论不对外展示；作者可看到必要的状态提示。

#### 点赞与举报

- 已登录用户可对资讯和已公开评论点赞或取消点赞。
- 已登录用户可举报资讯评论，举报时选择预设原因并可补充说明。
- 同一用户对同一对象的重复举报应合并处理。
- 举报、审核和处置记录由既有工具或人工流程维护，不在首版用户端开放管理入口。

### 4.4 主队

#### 主队选择

- 用户首次登录后，系统必须先进入主队选择界面。
- 主队选择界面以俱乐部图标和名称列表展示可选球队，点击任一项即可设为主队。
- 主队选择界面提供跳过入口；跳过后用户可继续使用产品，但底部主队按钮保持未选择状态。
- 用户可在后续通过主队入口重新进入主队选择界面并修改已选主队。

#### 主队入口与主队页

- 底部导航中的主队按钮在已选主队时显示对应俱乐部图标；未选主队时显示加号。
- 点击底部主队按钮后，若已选择主队，则进入主队页；若未选择主队，则进入主队选择界面。
- 主队页展示该队近期比赛、赛程赛果摘要、主队新闻和快速进入球队详情的入口。
- 主队页仅针对用户选定的单一主队，不同时展示多个主队。

### 4.5 账号、关注与收藏

- 登录后支持关注球队、球员和赛事；同一对象不可重复关注。
- 关注列表按对象类型分组，并提供进入详情页和取消关注的能力。
- 登录后收藏的资讯在跨设备场景下保持同步。
- 退出登录后，服务端个人数据不在本机公开展示；本地离线缓存按账号隔离或在退出时清除。

### 4.6 提醒与通知

- 推送通知仅在用户明确授权后启用，并在“我的”页展示当前授权状态。
- 用户可分别控制关注对象提醒和重大赛事提醒。
- 关注对象提醒包括：开赛前提醒、赛果提醒、重要资讯提醒。
- 重点提醒覆盖 WSL 赛程节点和用户关注对象，不依赖用户是否关注具体对象。
- 用户可关闭全部通知，且关闭后不再发送推送。
- 未授权、系统不支持推送或授权被撤回时，产品应提供非阻塞说明，不影响正常浏览。

## 5. PWA 与非功能需求

### 5.1 PWA 能力

- 支持在兼容浏览器中安装为独立应用。
- 提供应用图标、名称、启动页和适配移动端的显示模式。
- 首次联网访问后，缓存应用外壳、最近浏览资讯和近期资讯列表。
- 离线时可打开已缓存内容，并明确标识离线状态和内容缓存时间。
- 离线时访问未缓存页面、实时数据或登录/评论操作，应显示可理解的联网提示，不得制造提交成功的假象。
- 恢复网络后自动刷新可更新内容；用户主动刷新应优先获得最新数据。

### 5.2 性能与兼容性

- 移动端优先，适配常见手机、平板和桌面浏览器。
- 首屏应优先展示文字、关键图片和焦点赛事，非关键内容延迟加载。
- 图片应提供压缩版本、尺寸信息和加载失败降级。
- 页面需具备基础无障碍能力：语义化标题、可识别的按钮名称、键盘可操作、足够的文本与背景对比度。

### 5.3 视觉风格

- 产品整体以紫色 `#64077E` 和白色为主视觉，白色作为主要背景色，紫色用于品牌、重点按钮、选中状态和关键强调。
- 整体风格应专业、克制、清晰，避免花哨、娱乐化或过度装饰。
- 新闻、数据、主队和社区页面应保留足够留白，不使用过密列表，不在同一屏堆叠过多信息。
- 新闻栏目图片统一使用四角圆润的横向长方形，不使用正方形图片；同一页面内图片圆角保持一致。
- 新闻图片默认采用 `16:9` 或接近的横向资讯图比例，移动端展示时不得裁切到影响主体识别。

### 5.4 隐私与安全

- 仅在实现关注、收藏、评论和通知所需范围内收集账户与设备信息。
- 推送订阅、登录凭据和用户互动请求必须通过安全连接传输。
- 对评论文本进行输入校验与富文本/脚本安全处理。
- 在隐私政策和通知授权说明中明确账户数据、关注数据和推送订阅的用途。

## 6. 数据接口边界

### 6.1 接入策略

首版通过数据访问层对接第三方赛事数据服务。前台业务模块不得直接依赖特定供应商字段或接口地址，以便替换供应商、补充人工数据或增加多个数据源。

### 6.2 必备领域数据

| 领域 | 最低数据能力 |
| --- | --- |
| 赛事 | WSL 名称、赛季、地区、赛事类型、标识、展示图片 |
| 比赛 | 对阵、时间、比赛场地、比分、比赛事件、基础技术统计 |
| 积分榜 | 排名、球队、场次、胜平负、进失球、净胜球、积分、更新时间 |
| 球队 | 名称、标识、所属赛事、所拥有球员、近期赛程赛果、俱乐部介绍 |
| 球员 | 名称、头像、原文名、国籍、出生时间、位置、所属俱乐部、转会记录、基础资料、赛季基础数据、俱乐部官网的介绍 |
| 内容关联 | 资讯与赛事、球队、球员的关联标识 |

### 6.3 数据质量与降级

- 每个可见的数据集应包含来源标识和最近更新时间。
- 接口延迟、失败或返回不完整数据时，前台不得中断整页资讯阅读。
- 优先展示最后一次成功缓存的数据，并标记“数据可能已过期”。
- 对无可用数据的区域，提供简洁的空状态、错误说明和重试操作。
- 供应商选择、调用频率、版权许可、字段映射及数据 SLA 在技术选型阶段另行确认。

## 7. 首版验收标准

### 7.1 用户主路径

1. 游客可从数据、新闻、社区和我的页面进入对应内容，搜索内容，并浏览已审核评论。
2. 用户可查看 WSL 赛程、赛果、积分榜、球队页、球员页和比赛详情中的基础数据。
3. 用户在比赛详情页向下滑到底部后，可看到本场比赛的阵型与战术解读，或明确的“暂未提供”状态。
4. 用户首次登录后会进入主队选择界面，可选择主队或跳过。
5. 用户选择主队后，底部主队按钮显示对应俱乐部图标；未选择时显示加号。
6. 用户点击底部主队按钮后，可进入主队页查看近期比赛和主队新闻。
7. 用户从球队球员名单或比赛阵容点击有效球员头像后，可进入正确的球员数据页。
8. 用户从球员数据页点击有效的所属俱乐部标识后，可进入正确的球队数据页。
9. 用户登录后可关注球队、球员或赛事，收藏资讯，并在“我的”页查看和管理这些内容。
10. 用户登录后可提交评论；评论在审核通过前仅作者可见，其他用户不可见。
11. 用户可对公开评论和资讯点赞，并可举报评论。
12. 用户授权推送后，可收到关注对象及 WSL 重点赛程的规定提醒；撤回授权或关闭开关后停止推送。
13. 用户安装应用并联网浏览资讯后，可在断网时阅读已缓存的近期内容。

### 7.2 异常与边界

- 游客尝试评论、点赞、关注、收藏或设置提醒时，应被引导登录，不丢失当前阅读上下文。
- 数据接口不可用时，页面显示缓存数据或明确错误状态，并展示最后更新时间。
- 取消或延期比赛必须按接口状态更新，不能仍显示为正常进行。
- 关联球员或俱乐部缺失、已下线或无数据页时，头像或标识不得跳转；图片加载失败时仍展示文字替代信息。
- 用户离线提交评论、关注或点赞时，必须明确提示操作未完成；首版不要求离线排队提交。
- 未通过审核、被删除或被屏蔽的评论不得通过列表、搜索或直接链接对其他用户可见。
- 窄屏和桌面端的核心路径均可完成，文本、操作按钮、可点击头像/标识和数据表不应遮挡或溢出。
- 主要页面应符合紫色 `#64077E` 与白色为主的专业视觉风格；新闻图片应为四角圆润的横向长方形，页面信息不得拥挤或重叠。
